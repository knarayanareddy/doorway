## What is not written or not done

- A deployed edge. The Worker has been run for real only locally: on `node:sqlite` in the unit tests, and on workerd with a local D1 via `npm run smoke:workerd`. Neither is Cloudflare's D1 service; a first deploy may still surface differences.
- The 15-minute non-developer install, recorded. The artifact exists; the test with a person does not. That needs a person on camera.
- Discourse. It needs Docker, Postgres and Redis.
- A named human reviewer for false-positive reports (`docs/10-false-positive-review.md`).
- A production signing key (the pinned key is a dev key).
- Trigger sources. Doorway is the response layer; see `docs/08-trigger-adapters.md`.
- Everything that needs an outside party: see `docs/07-review-response.md`.

## Commands

```bash
npm ci
npm run verify        # the whole static + unit gate: shared modules, safety, eslint, tests, routes, privacy, copy, docs
npm run e2e           # Chromium, Firefox and WebKit against the real Worker; needs `npx playwright install chromium firefox webkit`
npm run e2e:chromium  # faster loop
npm run smoke:workerd # the Worker on the real Workers runtime (workerd) with a local D1; no account needed
npm run verify:wordpress # the generated plugin inside a real WordPress (needs php)
npm run status        # live counts and gate state
npm run build         # dist/door, dist/v<version>/doorway.min.js (+ SRI), dist/wordpress, dist/discourse
npm run sign          # re-sign routes.nl.json after editing routes (needs the signing key)
npm run check:pilot   # what is still missing before a pilot (expected to fail today)
npm run demo          # mock platform :8789 + Door/edge :8788
npm run e2e:hosted    # the hosted demo's server on two different origins, in a real browser (docs/15)
npm run demo:labs     # the same, with 30 days of synthetic data in the Desk and the labs shapes on (labs.html)
```

`npm test` is defined once in `package.json`; CI calls `npm run verify` and `npm run e2e`, nothing else.

## What the gates are, and are not

- **The privacy gate is a tripwire, not proof.** `eslint.config.js` restricts XHR, `Image`, WebSocket, `sendBeacon`, cookies, eval, geolocation, extra storage and `fetch` outside `send.js`; `scripts/gate-privacy.mjs` adds an AST scan for forbidden identifiers and checks that every `/v1/...` path in shipped code has a handler. It cannot see through dynamic access like `window['fe'+'tch']`.
- **The evidence is `test/e2e/network.spec.js`** (every request the real Door makes in a real browser: one host, `POST` for writes, seven fields, no cookies, one storage key) **and the Door's CSP**, which makes the browser refuse any other connection. `host-adversary.spec.js` is the evidence for the host-as-adversary claim.
- **`lint:copy` cannot judge tone.** It checks every string in every language for assumed intent, confidentiality words, time-unit numbers and the 20-word rule. Native-speaker review of Dutch and German is a human step.
- **`check:routes` fails when the bundle's signature, honesty or expiry is wrong**, and warns two weeks before it lapses.

## Deploying the edge

```bash
npx wrangler d1 create doorway-agg
npx wrangler d1 execute doorway-agg --file=edge/schema.sql --remote
# set DOOR_ORIGIN in edge/wrangler.toml to the Worker's real origin, then:
DOOR_ORIGIN=https://door.example.org CDN_BASE=https://cdn.example.org npm run build
cd edge && npx wrangler deploy
```

Create an install with a verify token and a Desk token (store only the SHA-256 of the Desk token):

```sql
INSERT INTO installs (id, domain, verify_token, desk_token_hash, daily_cap)
VALUES ('inst_xxxxxx', 'platform.example', '<random>', '<sha256 hex of the desk token>', 5000);
```

The platform then adds `<meta name="doorway-verify" content="<random>">` (or a DNS TXT at `_doorway.<domain>`) and calls `POST /v1/verify {"i":"inst_xxxxxx"}`.

## The acceptance tests that matter

1. **A non-developer installs it in under fifteen minutes, on camera.** Not yet run. The install is one script tag with data attributes (or the WordPress plugin); see `INSTALL.md`.
2. **The network panel shows seven fields and zero cookies.** Asserted by `network.spec.js`; also demonstrable live with `npm run demo`.
3. **Five consecutive triggers produce five different responses.** Asserted in `shift.test.js` for both spaced and burst sequences.
